# Инструкция для владельца

Коротко: что где менять и как проверить, что всё работает.
Текущая версия подготовлена для портфолио, работает без интернета двойным щелчком по `index.html`.

---

## 1. Что где лежит

| Файл | Что внутри |
| --- | --- |
| `index.html` | главная страница |
| `style.css`, `style-panel.css` | оформление сайта и служебных страниц |
| `js/config.js` | **все настройки**: телефон, адрес, часы, карта, канал заявок, пароль, пометки |
| `data/menu.js` | меню и цены, включая категорию «Пекарня» |
| `data/photos.js` | список имён фото блюд для подсказок в панели |
| `data/reviews.js` | отзывы для блока «Отзывы» |
| `data/about.js` | зёрна и команда для блока «Кто стоит за кофе» |
| `zakazy.html` | журнал заявок (служебная страница) |
| `admin.html` | панель меню и отзывов (служебная страница) |
| `politika.html` | политика конфиденциальности |
| `assets/img/` | картинки |

Служебные страницы не видны в меню сайта, закрыты от поисковиков и спросят пароль
при открытии. Пароль — только от случайного открытия, подробнее в разделе 16.

## 2. Контакты, адрес и часы

Откройте `js/config.js` любым текстовым редактором (например, «Блокнот»).
Меняйте только текст в кавычках, кавычки и запятые не трогайте.

```js
phone: "+7 (000) 000-00-00",   // как показывать на странице
phoneHref: "+70000000000",     // то же число без пробелов — для звонка с телефона
email: "hello@example.com",
address: "ул. Хххххххх, д. ХХ, 1 этаж, вход со двора",
addressShort: "ул. Хххххххх, д. ХХ",
postalCode: "XXXXXX",          // индекс-заглушка
hoursLines: ["пн–пт с 8:00 до 21:00", "сб–вс с 9:00 до 22:00"],
holidayNote: "В праздничные дни работаем по расписанию выходных.",
coords: { lat: 55.7602, lon: 37.6187 },
```

После правки сохраните файл и обновите страницу (F5).

Важно: `phone` и `phoneHref` — одно и то же число в двух видах.
Если поменяли одно, поменяйте и второе.

**Адрес-заглушка.** Строки с `Хххххххх`, `ХХ`, `XXXXXX`, телефон из нулей и
`example.com` — демонстрационные. Перед сдачей замените их на настоящие:
в `config.js`, в `legal.legalAddress`, в `index.html` (в разметке для поисковиков
и в запасном тексте без скриптов), в `politika.html`, в `robots.txt` и `sitemap.xml`.

**Статус «Открыто до 21:00».** Он считается сам из `openingHours` — массива
с днями недели на английском (`Monday`, `Saturday` и так далее) и временем
`opens` / `closes`. Обновляется раз в минуту. Если часы поменяли, правьте
и `hoursLines` (текст для людей), и `openingHours` (для расчёта).

**Мессенджеры:** `whatsapp`, `telegram`, `vk` — ссылки. Сейчас там демонстрационные адреса.

## 3. Меню и цены

1. Откройте `admin.html` двойным щелчком и введите пароль из `js/config.js`
   (сейчас `demo2026`).
2. Поправьте названия, описания, цены, метки («хит», «новинка»).
3. Кнопками «Выше», «Ниже», «Добавить», «Удалить» меняйте порядок и состав.
4. Нажмите **«Скачать menu.js»** — браузер сохранит файл `menu.js`.
5. Положите этот файл в папку `data` вместо старого.
6. Обновите сайт — меню обновилось.

Если скачивание не сработало: раскройте строку «Показать текст файла»,
скопируйте текст и вставьте его в файл `data/menu.js` вручную.

Кнопка «Сбросить к исходному» возвращает меню, которое лежит в `data/menu.js`.

Правки в панели хранятся как черновик в этом браузере. На сайт они попадают
только после замены файла — это сделано нарочно, чтобы нельзя было испортить сайт одним щелчком.

Сейчас в меню четыре категории: «Кофе», «Десерты», «Завтраки», «Пекарня» (20 позиций).
Категория «Пекарня» и цены в ней (180, 150, 170 ₽) — демонстрационные, как и всё остальное.

Если в `js/config.js` поставить `bakery: false`, категория «Пекарня» исчезнет с сайта,
а в шапке и подвале вместо «кофейня и пекарня» станет просто «кофейня».
В панели категория останется — она просто не показывается на сайте.

## 4. Фотографии

Все фотографии уже лежат в `assets/img/`. Ничего генерировать и переименовывать не нужно.
Чтобы заменить снимок, положите свой файл **с тем же именем** вместо старого.

| Файл | Где используется | Размер |
| --- | --- | --- |
| `hero.jpg` (+ `hero-640.webp`, `hero-1280.webp`) | первый экран | 1600×1100 |
| `interior-1.jpg` (+ webp) | плитка галереи «Зал у окна» | 1200×900 |
| `dessert-1.jpg` (+ webp) | плитка галереи «Чизкейк с черникой» | 1200×900 |
| `latte-gallery.jpg` (+ webp) | плитка галереи «Латте с рисунком» | 1536×1024 |
| `team/barista.jpg`, `team/roasting.jpg` (+ webp) | блок «Кто стоит за кофе» | 1536×1024 |
| `beans.jpg` | тихий фон галереи | 512×512 |
| `og.jpg` | карточка для соцсетей | 1200×630 |

Лёгкие версии `.webp` подключаются в разметке через `<picture>`; браузер сам выбирает
подходящий файл. Если webp удалить, покажется обычный `.jpg` — страница не сломается.

У фото с пропорцией 3:2 (`latte-gallery.jpg` и командные) в разметке указаны
фактические размеры `width="1536" height="1024"` — это убирает сдвиг страницы при загрузке.
У фото блюд — `width="1200" height="900"`.

Тексты подписей к фото («Зал у окна», «Латте с рисунком» и т. д.) лежат в `index.html`
в разделе `gallery`.

### Фото блюд

Фото блюда появляется в блоке «Атмосфера» на месте одной из трёх градиентных плиток,
вместе с названием и ценой.

1. Положите файл в папку `assets/img/dishes/`. Имя — латиницей, без пробелов,
   кадр горизонтальный (лучше 4:3, сейчас все файлы 1200×900, 70–92 КБ).
   Уже лежат: `syrniki.jpg`, `kruassan.jpg`, `cheesecake.jpg`, `medovik.jpg`,
   `filtr-v60.jpg`, `cold-brew.jpg`, `tart-grusha.jpg`, `sendvich.jpg`.
2. Откройте `data/photos.js` и впишите имя файла в список:
   `window.DISH_PHOTOS = ["syrniki.jpg", "kruassan.jpg"];`
   Это только подсказки для панели — на показ фото список не влияет.
3. Откройте `admin.html` и у нужной позиции меню заполните поле «Фото блюда»
   (можно выбрать из подсказок). Кнопка «Убрать фото» очищает поле.
4. Нажмите «Скачать menu.js» и замените файл `data/menu.js`.
5. Обновите сайт.

Порядок плиток — порядок позиций в меню: сначала «Кофе», потом «Десерты», затем «Завтраки».
Первые три позиции с фото занимают три свободных места; если фото больше,
остальные плитки появляются новым рядом ниже. Если файла нет, плитка остаётся
градиентной — битой картинки не будет. Если фото нет ни у одной позиции,
блок «Атмосфера» выглядит точно как раньше.

Плитки всегда встают ровными рядами: на широком экране по три, на телефоне по две.
Если в последнем ряду остаётся одна плитка, она растягивается на всю ширину —
получается широкий кадр, пустого места не остаётся.

### Фон из зёрен

`beans.jpg` — текстура обжаренных зёрен. Стоит очень тихим фоном в блоке
«Атмосфера» (там, где галерея).

- **Заменить:** положите свой снимок с именем `beans.jpg` в ту же папку.
  Лучше бесшовный, вид сверху, светлый фон.
- **Сделать заметнее или тише:** в `style.css` найдите `section--beans` и поменяйте
  `opacity: 0.1` (больше — заметнее, меньше — тише).
- **Убрать совсем:** в `index.html` удалите слово `section--beans` в строке
  `<section class="section section--beans" id="gallery"`. Файл `beans.jpg` можно оставить.

## 5. Заявки на бронь

Сейчас сайт работает на заглушке: заявка **никуда не отправляется**,
а сохраняется в памяти браузера. Посмотреть её можно в журнале:

1. Отправьте заявку через форму на сайте.
2. Откройте `zakazy.html` и введите пароль из `js/config.js` (сейчас `demo2026`).
3. В таблице будет заявка: имя, телефон, дата, гости, комментарий.
4. Статус меняется выпадающим списком: «Новая», «Подтверждена», «Отменена».
5. «Экспорт в CSV» — скачать таблицу для Excel.
6. «Очистить всё» — удалить все заявки (спросит подтверждение).

Пока скрипты не загрузились, на экране успеха стоит «б/н»; после отправки
скрипт подставляет реальный номер, нумерация начинается с № 128.
Демонстрационные пояснения и ссылка на журнал управляются пометками
`demoNotice` и `demoJournal` (раздел 12).

Где лежат данные: в памяти браузера на этом устройстве. На другом компьютере заявок не будет.
После очистки истории браузера они тоже пропадут.

## 6. Как включить настоящую отправку заявок

В `js/config.js` две строки:

```js
bookingChannel: "stub",   // сейчас: заявка остаётся в браузере
webhookUrl: "",           // адрес, куда отправлять заявку
```

Чтобы заявки уходили на сервер:

1. Получите адрес приёма заявок (например, от подрядчика или из сервиса форм).
2. Впишите его в `webhookUrl`.
3. Поменяйте `bookingChannel` на `"webhook"`.
4. Сохраните файл и проверьте: отправьте тестовую заявку и посмотрите, пришла ли она.

Заявка уходит обычным запросом POST в формате JSON. Ключи и пароли в такой запрос
не помещайте — только адрес.

Если канал `"webhook"`, а заявка не пришла — сначала проверьте:
- правильный ли адрес в `webhookUrl` (без опечаток, с `https://`);
- не блокирует ли браузер запрос (посмотрите вкладку «Сеть» в инструментах разработчика);
- работает ли сам приёмник заявок.

Пока `bookingChannel: "stub"`, заявки надёжно лежат в журнале — это и есть
страховка для демонстрации.

## 7. Демо-режим и боевой режим

```js
mode: "demo",   // на странице видна плашка «Демонстрационный макет»
```

- `"demo"` — включает приём заявок в браузере; плашка, пояснения и ссылка на журнал
  показываются только если соответствующие пометки включены.
- `"live"` — плашка и пояснения убираются.

Дополнительно каждую пометку можно выключить отдельно через `marks` (раздел 12).
Сейчас оставлен `mode: "demo"` для приёма заявок в браузере, но все девять
пометок выключены — на странице нет ни плашки, ни демо-подписей.

Перед настоящим запуском: поменяйте реквизиты в `legal`, телефон, почту, адрес,
домен в `domain`, пароль в `servicePassword`, затем `mode` на `"live"`.

## 8. Карта

Это единственное обращение страницы к другому сайту. Карта появляется сама,
если браузер видит интернет. Кнопки «Показать карту» больше нет.

Если интернета нет, сразу остаётся запасная панель: адрес и ссылка «Открыть
в Яндекс Картах». Если карта не ответила, через 12 секунд появляется такая же
подсказка — страница не зависит от чужого сервера.

Координаты — в `js/config.js`, строка `coords`. Широта (`lat`) и долгота (`lon`)
через запятую. Взять их можно в Яндекс Картах: правый щелчок по точке → «Что здесь?».
Там же демонстрационные координаты центра Москвы; перед сдачей замените их.

## 11. Видео в первом экране

Сейчас на первом экране фотография. Можно поставить короткий ролик без звука —
он будет включаться сам и крутиться по кругу.

1. Сделайте папку `assets/video/`, если её ещё нет.
2. Положите туда файл с именем `hero.mp4`.
3. В `js/config.js` впишите путь:

```js
heroVideo: "assets/video/hero.mp4",   // было: ""
```

4. Сохраните файл и обновите страницу. Фото заменится на видео, код менять не нужно.

Как это устроено:

- пустая строка `heroVideo: ""` — показывается фото (так сейчас);
- пока видео грузится, видно фото; если файла нет или браузер не смог его показать,
  остаётся фото — сайт не ломается;
- если человек включил в системе «меньше движения», видео не появится: будет фото;
- звука у ролика нет, поэтому браузеры разрешают включать его автоматически.

Совет: 5–10 секунд, до 3–5 МБ, горизонтальный кадр. Большой файл долго грузится.

## 12. Пометки в подвале и наверху

За это отвечает блок `marks` в `js/config.js`:

```js
marks: {
  demoBanner: false,  // верхняя тёмная полоса «Демонстрационный макет…»
  photoCredit: false, // подпись к фото в подвале
  legalNote: false,   // «Реквизиты демонстрационные…»
  disclaimer: false,  // «Демонстрационный макет. Данные вымышлены.»
  demoForm: false,    // пояснение под заголовком формы брони
  demoNotice: false,  // «Так выглядело бы уведомление…» на экране успеха
  demoJournal: false, // ссылка «Журнал заявок (демо)»
  demoCookie: false,  // фраза «В демо-версии все данные остаются…» в плашке cookie
  schoolProject: false // «Учебный проект.» в подвале
},
```

`true` — пометка видна, `false` — её нет совсем (пустого места тоже не остаётся).

`demoBanner` работает и для поисковиков: когда он выключен, скрипт убирает фразу
«Демонстрационный макет, данные вымышлены.» и из описания страницы.
В текущей версии эта фраза убрана и прямо в `index.html`, поэтому описание чистое
даже без скриптов.

`demoCookie` прячет только одну фразу про демо-версию. Остальной текст плашки
про файлы cookie остаётся — он нужен и на боевом сайте.

`demoNotice` и `demoJournal` проверяются и в форме брони: при `false` эти блоки
не появятся даже после отправки заявки.

**В текущей версии все девять пометок уже выключены** (`false`) — страница готова
к портфолио и выкладке в сеть. Чтобы вернуть учебный вид, поставьте `true` —
пометки снова появятся.

Если скрипты в браузере выключены, пометки видны всегда — это сделано нарочно,
чтобы предупреждение о макете нельзя было потерять.

## 13. Реквизиты владельца: ИП, самозанятый или физлицо

В `js/config.js` есть блок `legal`. Первая строка — тип владельца:

```js
legal: {
  type: "ip",                            // "ip" — ИП, "self" — самозанятый, "person" — физлицо
  name: "Иванов Иван Иванович",
  fullName: "ИП Иванов Иван Иванович",   // как писать в подвале
  inn: "000000000000",
  ogrnip: "000000000000000",             // нужно только для ИП
  legalAddress: "XXXXXX, г. Хххххххххх, ул. Хххххххх, д. ХХ",
  note: "Реквизиты демонстрационные и не являются настоящими."
},
```

Подвал собирается сам, по типу:

| type | Какие строки появятся |
| --- | --- |
| `"ip"` | Предприниматель, ИНН, ОГРНИП, Юридический адрес |
| `"self"` | Самозанятый, ИНН, Статус («Налог на профессиональный доход»), Адрес |
| `"person"` | Владелец, ИНН (если поле пустое — строки не будет), Адрес |

Телефон и почта добавляются в конце всегда. Если скрипты выключены, в подвале
остаётся запасной вариант — как для ИП.

## 14. Что нужно по закону

Ниже — короткий список того, о чём стоит подумать до запуска.
**Это не юридическая консультация.** Перед запуском уточните у юриста,
что именно нужно в вашем случае.

**1. Уведомление в Роскомнадзор.**
Сайт собирает имя и телефон — это персональные данные. Владелец обязан отправить
в Роскомнадзор уведомление о том, что будет обрабатывать персональные данные.
Подаётся через сайт ведомства, бесплатно, **до того** как начнёте собирать заявки.

**2. Согласие и политика — обязательные части.**
Галочка «Согласен на обработку персональных данных» в форме уже есть,
страница политики конфиденциальности (`politika.html`) тоже есть.
Это не украшение: без них собирать данные нельзя. Текст политики перед запуском
проверяет юрист, реквизиты в нём подставляются из настроек.

**3. Где хранить заявки.**
Закон (152-ФЗ) требует, чтобы данные российских клиентов хранились на серверах
**в России**. Значит нельзя складывать заявки в зарубежные сервисы — например,
в Google Таблицы или в зарубежные конструкторы форм. Подойдёт российский
хостинг или сервер, либо российский сервис приёма заявок.

**4. Срок хранения.**
Держать заявки «навсегда» нельзя. Определите срок (например, один год после визита)
и удаляйте данные, когда срок вышел. В политике этот срок указан — держите его
в согласии с тем, как вы на самом деле храните заявки.

**5. Онлайн-оплата.**
Если когда-нибудь появится оплата на сайте, начнут действовать отдельные
требования: касса, чеки покупателю, уведомления. Сейчас оплаты нет и это не нужно.

Что уже сделано на этом сайте в эту сторону: согласие в форме, страница политики,
плашка cookie с выбором «Только необходимые», счётчик посещений выключен,
пометки о том, что данные демонстрационные.

## 15. Что осталось за рамками демо

- Настоящая отправка заявок и почта — только после подключения `webhookUrl`.
- Онлайн-оплата не подключена и не нужна.
- Настоящие фото, реквизиты, домен и счётчик подставляет владелец.

## 16. Пароль на служебных страницах

`admin.html` и `zakazy.html` при открытии спрашивают пароль. Сейчас он `demo2026`
в строке `servicePassword` файла `js/config.js`.

**Важно:** это не защита от взлома. Пароль лежит в открытом файле, и любой
желающий может его прочитать. Загородка нужна только для того, чтобы случайный
человек не попал в служебную страницу. Не используйте этот же пароль где-то ещё.

- Неверный пароль или закрытое окно ввода — вместо страницы появляется
  «Доступ закрыт» с кнопкой «На главную».
- Менять пароль: поменяйте строку в `config.js` и сохраните файл.
- Настоящую защиту (вход по логину с сервера) нужно делать отдельно —
  на статическом сайте её нет и быть не может.

## 17. Отзывы

Отзывы лежат в `data/reviews.js`. На сайте их показывает `js/main.js`,
в панели `admin.html` — нижний блок «Отзывы на сайте».

1. Откройте `admin.html`, введите пароль.
2. В блоке «Отзывы на сайте» поправьте имя, роль, текст, источник, ссылку,
   дату и оценку. Кнопки «Выше», «Ниже», «Удалить» меняют порядок и состав.
3. Кнопка «Добавить отзыв» создаёт новую пустую карточку.
4. Галочка «Показывать раздел «Отзывы» на сайте» — это поле `enabled`.
   Если её снять, раздел исчезнет со страницы полностью.
5. Нажмите «Скачать reviews.js» и замените файл `data/reviews.js`.
6. Обновите сайт.

Правки отзывов, в отличие от меню, не сохраняются черновиком в браузере:
скачали файл — заменили файл. Если скачивание не сработало, раскройте
«Показать текст файла reviews.js» и скопируйте текст вручную.

В портфолио-версии три отзыва честно подписаны «Пример отзыва», у них стоит
`demo: true`, пустые дата и оценка. Раздел включён, чтобы показать работу блока.
Перед настоящим заказчиком замените отзывы настоящими или выключите раздел
полностью: `reviewsEnabled: false` в `js/config.js` либо `enabled: false`
в `data/reviews.js`. Достаточно любого из двух выключателей.

## 18. Зёрна и команда

Блок «Кто стоит за кофе» берёт данные из `data/about.js`:

- `beans` — три зёрна: название, страна, обжарка и короткая заметка о вкусе.
- `team` — две карточки: имя или роль, должность, текст и имя файла из
  `assets/img/team/`.

Чтобы добавить человека, допишите объект в массив `team` и положите фото
в `assets/img/team/`. В `js/main.js` для него автоматически соберётся `<picture>`
с webp-версиями `…-640.webp` и `…-1000.webp`. Если webp нет, покажется обычный `.jpg`.

Названия зёрен — общеизвестные регионы, без выдуманных поставщиков.
Если захотите заменить тексты, правьте `data/about.js` — `index.html` трогать не нужно.

## 20. Доступность и клавиатура

- По клавише Tab первой появляется ссылка «Перейти к содержимому», дальше идёт обычный порядок элементов.
- Фокус везде виден: вокруг ссылок, кнопок и полей появляется обводка.
- Пока открыта плашка cookie, Tab ходит только по её кнопкам — так нельзя случайно
  уйти дальше, не выбрав ответ.
- Подписи у фото и кнопок понятные, без слов «демонстрационная» в озвучке для слабовидящих.
- На телефоне подписи к плиткам галереи крупнее: 14 пикселей, на узком экране 13.

## 21. Версия для портфолио и выкладка в сеть

1. Все девять пометок уже выключены в `js/config.js` (`marks: false`) — ничего
   включать перед показом не нужно.
2. Перед выкладкой укажите настоящий адрес сайта в трёх местах:
   `js/config.js` (поле `domain`), `robots.txt` и `sitemap.xml`. В этой копии
   там стоит плейсхолдер `Dmitrii-trotskii.github.io/kofe-in-ja/`.
3. Загрузите содержимое папки на любой статический хостинг целиком — вместе
   с картинками, стилями и скриптами.
4. Служебные страницы `admin.html` и `zakazy.html` можно удалить из выложенной
   копии — сайт без них работает.
5. Пароль `demo2026` — не защита, только загородка от случайного открытия.
6. Отзывы подписаны «Пример отзыва»; перед настоящим заказчиком замените их
   настоящими.

## 22. Как выложить на GitHub Pages

1. Зарегистрируйтесь на GitHub и создайте публичный репозиторий (хранилище)
   с именем `kofe-in-ja` (или другим).
2. Загрузите в репозиторий все файлы из этой папки — можно просто перетащить
   их в веб-интерфейсе GitHub (включая скрытый файл `.nojekyll`).
3. Откройте настройки репозитория: **Settings → Pages**. В блоке «Build and
   deployment» выберите **Branch: main**, **Folder: / (root)** и нажмите
   **Save**.
4. Логин `Dmitrii-trotskii` и имя репозитория `kofe-in-ja` уже подставлены в `js/config.js`,
   `robots.txt` и `sitemap.xml`. Если назовёте репозиторий иначе — замените `kofe-in-ja`.
5. Адрес сайта будет: `https://Dmitrii-trotskii.github.io/kofe-in-ja/` (с вашим логином
   и именем репозитория).
6. Откройте сайт на телефоне и проверьте: главная, меню, переходы на страницы,
   картинки и форму.
